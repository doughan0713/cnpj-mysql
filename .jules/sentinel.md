## 2026-08-07 - Parameterization of Metadata Tables and Secure URL Construction
**Vulnerability:** Ingestion scripts previously used f-string SQL interpolation for updating metadata values (`dataReferencia` and `qtde_cnpjs`) within the `_referencia` table, leading to potential SQL injection vulnerabilities if the metadata strings were ever modified or manipulated. Additionally, database connection parameters were hardcoded directly in the python files, presenting secrets exposure risks and f-string URL injections when using unescaped passwords.
**Learning:** Legacy projects often hardcode database parameters and concatenate SQL queries when interacting with non-user-facing tables or when they assume that local data is inherently trusted. However, even internal system variables or metadata extracted from external source filenames can serve as injection vectors.
**Prevention:** Always use parameterized SQL statements with bind parameters (`:param_name`) via SQLAlchemy `text()` for any dynamic insertion. Securely construct database connection URLs using programmatic builders like `sqlalchemy.engine.URL.create` instead of f-string URI building, and securely load environment variables from external `.env` templates with safe parsing.
