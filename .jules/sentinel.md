## 2026-07-22 - SQL Injection in Database Reference Table Ingestion
**Vulnerability:** The data ingestion scripts (`dados_cnpj_mysql.py` and `dados_cnpj_postgres.py`) populated the `_referencia` metadata table using f-string interpolation for SQL query generation. Specifically, the variable `dataReferencia` was concatenated directly into the SQL string when inserting the CNPJ baseline data's reference date, creating an SQL injection vulnerability.
**Learning:** Legacy scripting patterns often prioritize simple string formatting or interpolation over parameterized queries when handling values that are thought to be internally generated or safe, but any dynamic inputs inserted directly into raw SQL statements open risks if those variables are ever influenced by external filenames or configuration parameters.
**Prevention:** Always parameterize all database queries, including metadata tracking and simple reference insertions, by using SQLAlchemy's `text()` with bind parameter dictionaries (e.g., `engine.execute(text("insert into ... values (:ref, :val)"), {"ref": ..., "val": ...})`), ensuring variables are never directly interpolated into the SQL command itself.
