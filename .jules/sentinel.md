## 2026-07-28 - SQL Injection in Metadata Insertion and Insecure Database Parametrization
**Vulnerability:** Ingestion scripts (MySQL and PostgreSQL) previously used f-string interpolation to insert calculated database parameters and metadata into the `_referencia` metadata table. They also defined connection parameters using hardcoded configurations or direct string interpolation in the connection URL string. This created direct risks of SQL Injection and credential escaping failures.
**Learning:** SQL Injection risks are not limited to user-facing applications. Batch processing pipelines and ingestion scripts that dynamically format SQL or construct connection URLs with unescaped strings can be compromised if environment values, folder names, or scraped metadata are manipulated.
**Prevention:** Always use parameterized SQL statements with SQLAlchemy's `text` and parameter dictionaries (e.g., `:param` with bind params) instead of f-strings, even for internal metadata. Always utilize robust parsing like `sqlalchemy.engine.URL.create` to safely assemble database connection strings.
